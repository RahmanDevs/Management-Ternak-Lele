# Leleku automated tests

This folder contains executable tests and documentation for the catfish-farming management MVP. The existing 72 tests were moved out of `src/test/`, with additional boundary and UI recovery regressions. Application source remains in `src/`.

## Folder structure

```text
tests/
  setup.js                       Shared clock, storage, DOM mocks, and cleanup
  helpers/
    fixtures.js                  Reusable action payloads and state helpers
    renderApp.jsx                App rendering, routing, and form helpers
  unit/
    business.test.js             Calculations, business rules, roles, persistence
    boundaries.test.js           Invalid input, decimal and state-integrity cases
  integration/
    app.test.jsx                 Login, routes, daily logs, owner workflows
    regression.test.jsx          Persistence, recovery, dialogs, read-only UI
  docs/
    TEST_CASES.md                Inputs, steps, expected results, requirement mapping
    TEST_RESULTS.md              Verified execution results and remaining checks
  reports/
    latest.json                 Generated by test:report; ignored by Git
```

## Run the tests

Run commands from the project root, not from `tests/`. Use a Node.js version allowed by `package.json`; Node.js 24 LTS is recommended.

For a fresh checkout, install the locked dependencies:

```bash
npm ci
```

| Command                                             | Purpose                                                    |
| --------------------------------------------------- | ---------------------------------------------------------- |
| `npm test`                                          | Run all automated tests once.                              |
| `npm run test:unit`                                 | Run business-rule and boundary tests only.                 |
| `npm run test:integration`                          | Run React application integration tests only.              |
| `npm run test:watch`                                | Watch files and rerun affected tests; stop with Ctrl+C.    |
| `npm run test:report`                               | Run all tests and write `tests/reports/latest.json`.       |
| `npm test -- -t "SAL-06"`                           | Run one scenario by its stable test ID.                    |
| `npm test -- tests/integration/regression.test.jsx` | Run one test file.                                         |
| `npm run build`                                     | Verify production bundling; this is not a behavioral test. |

No running web server, database, or real farm data is required. Vitest discovers only `tests/**/*.test.{js,jsx}` through `vite.config.js`. Failed tests return a nonzero exit code suitable for CI. Each reporting run replaces the previous JSON report.

## What the tests execute

- Unit/business tests call the real calculations, validation, action handlers, and persistence functions. They cover successful, rejected, boundary, and regression scenarios.
- Integration tests render the real React application and store with React Testing Library in jsdom. They exercise routes, forms, confirmation handlers, rendered messages, and saved state.
- `user-event` drives clicks and selections. The `fill()` helper dispatches form change events; it does not simulate every keystroke.
- Integration tests use `MemoryRouter`. Production uses `HashRouter`, so deployment URLs and real hash navigation still require browser verification.

## Isolation and test data

Before each test, `setup.js` clears jsdom's localStorage and sessionStorage and freezes `Date` at `2026-11-11T03:00:00.000Z` (10:00 in Asia/Jakarta). Scheduling timers remain real so React and user interactions can complete normally. Date-sensitive fixtures are created inside each test after the clock is set.

The setup mocks scrolling and the missing native dialog methods. Dialog mocks only toggle the `open` attribute; they do not emulate browser layout, focus trapping, the top layer, or Escape-key behavior. Cleanup unmounts React, restores mocks and original dialog descriptors, and restores the clock after each case. Storage is isolated from the user's actual browser.

`fixtures.js` supplies a new batch in Kolam C (1,000 seedlings, Rp 300,000 seed cost, Rp 50,000 other cost), a 100 kg harvest, and a 50 kg unpaid sale at Rp 25,000/kg by default. Tests override individual fields to expose validation boundaries. Each test starts from a fresh seed unless it explicitly constructs a different state.

`openApp(route, role, state)` optionally seeds a session and saved state before mounting. It uses the real store and persistence layer, not mocked application logic. Generated record IDs are not compared with fixed UUIDs.

## Documentation and limitations

- [Test-case catalog and requirement mapping](docs/TEST_CASES.md)
- [Verified results and remaining manual checks](docs/TEST_RESULTS.md)

Scenario IDs such as `BND-04` are included in test names. Parameterized scenarios expand into multiple executed cases, so the number of IDs differs from the test count.

Passing tests establish only the assertions listed in the catalog. They are not proof of complete specification coverage, production security, browser compatibility, or accessibility compliance. No line/branch coverage percentage has been measured, and no real-browser automation is included.

## Adding a regression

1. Add a focused case to `unit/` or `integration/` with a unique scenario ID.
2. Use a fresh seed and specify the input or interaction that reproduces the problem.
3. Assert the externally meaningful result, including unchanged state for rejected mutations when relevant.
4. Update the catalog, run the full suite, and refresh the results document with verified output.
